## 3. Production Shortfall Engine

The shortfall engine compares:

- `predicted_output`
- `planned_target`

A shortfall is flagged when:

    predicted_output < planned_target

The shortfall amount is calculated as:

    shortfall = planned_target - predicted_output

Shortfall percentage is calculated as:

    shortfall_percent = (shortfall / planned_target) × 100

A zero shortfall is returned when predicted output meets or exceeds the planned target.

### Boundary validation

The following conditions were verified:

- Predicted output below target → shortfall flag `true`
- Predicted output equal to target → shortfall flag `false`
- Predicted output above target → shortfall flag `false`

## 4. Operational Risk Engine

The risk engine evaluates three operational conditions:

- Downtime
- Rainfall
- Blast delay

The configured trigger thresholds are:

| Condition | Threshold |
|---|---:|
| Downtime | 75.2 hours |
| Rainfall | 378.7 mm |
| Blast delay | 5 |

A condition is triggered when its value is greater than or equal to the configured threshold.

### Risk classification

Risk is determined from the number of triggered operational conditions:

| Triggered conditions | Risk level |
|---:|---|
| 0 | Low |
| 1–2 | Medium |
| 3 | High |

Production shortfall is reported separately and does not directly increase the operational risk level.

---

## 5. Individual Risk Rules

### 5.1 Downtime Rule

When downtime reaches or exceeds 75.2 hours, the downtime condition is triggered.

The recommendation severity is further determined using:

    downtime >= threshold × 1.25

This identifies severe downtime conditions.

Otherwise, a triggered downtime condition is treated as a downtime event requiring operational attention.

### 5.2 Rainfall Rule

When rainfall reaches or exceeds 378.7 mm, the rainfall condition is triggered.

The recommendation severity is further determined using:

    rainfall >= threshold × 1.25

This identifies severe rainfall conditions.

Otherwise, a triggered rainfall condition is treated as a high-rainfall event requiring operational attention.

### 5.3 Blast Delay Rule

When blast delay reaches or exceeds 5, the blast-delay condition is triggered.

The recommendation severity is further determined using:

    blast_delay >= threshold × 1.25

This identifies severe blast-delay conditions.

Otherwise, a triggered blast-delay condition is treated as a blast-delay event requiring operational attention.

## 6. Recommendation Engine

The recommendation engine combines production shortfall information with operational risk conditions.

Recommendations are generated only when their corresponding condition is triggered.

The recommendation action is selected according to the severity of the detected condition.

The actual prediction values used by the engine are obtained dynamically from the prediction record.

### 6.1 Shortfall-based recommendations

Shortfall severity is determined from the calculated shortfall percentage.

| Shortfall percentage | Recommendation category |
|---:|---|
| > 30% | Critical |
| 20%–30% | Significant |
| < 20% | Moderate |

### Critical production shortfall

For shortfall values above 30%:

    Critical production shortfall detected. Escalate production recovery actions and reallocate resources.

### Significant production shortfall

For shortfall values from 20% to 30%:

    Significant production shortfall detected. Review the production plan and optimize resource allocation.

### Moderate production shortfall

For shortfall values below 20%:

    Moderate production shortfall detected. Monitor production closely and make targeted operational adjustments.

The recommendation also includes:

- Predicted output
- Planned target
- Calculated shortfall percentage

These values are obtained from the prediction record.

---

### 6.2 Downtime-based recommendations

When the downtime threshold is triggered, the recommendation is selected based on severity.

### Downtime recommendation

    Downtime detected. Schedule preventive maintenance and optimize resource allocation.

### Severe downtime

    Severe downtime detected. Initiate urgent maintenance and reallocate operational resources.

The actual downtime value remains available in the API response for dashboard display.

---

### 6.3 Rainfall-based recommendations

When the rainfall threshold is triggered, the recommendation is selected based on severity.

### Rainfall recommendation

    High rainfall detected. Adjust the production schedule and prioritize safer operations.

### Severe rainfall

    Severe rainfall conditions detected. Restrict weather-sensitive operations and revise the production schedule.

The actual rainfall value remains available in the API response for dashboard display.

---

### 6.4 Blast-delay-based recommendations

When the blast-delay threshold is triggered, the recommendation is selected based on severity.

### Blast-delay recommendation

    Blast delay detected. Reprioritize delayed blasting activities to maintain production continuity.

### Severe blast delay

    Severe blast delay detected. Urgently reschedule delayed blasting activities to minimize production disruption.

The actual blast-delay value remains available in the API response for dashboard display.

## 13. Current Integration State

The current P5 recommendation endpoint consumes the generated P3 production prediction output file.

The risk and recommendation calculations are dynamic relative to the prediction records being consumed.

The recommendation engine does not manually assign a risk level or recommendation to an individual prediction record.

The following are calculated from the input prediction data:

- Risk level
- Triggered conditions
- Shortfall flag
- Shortfall amount
- Shortfall percentage
- Recommendation selection
- Recommendation severity
- Dynamic prediction values shown in recommendations

The current implementation does not directly invoke P4's `/predict-production` endpoint for every fresh request.

A future live orchestration flow can connect:

    Fresh operational input
            ↓
    P4 /predict-production
            ↓
    P3 production model
            ↓
    Fresh prediction
            ↓
    P5 Risk Engine
            ↓
    P5 Recommendation Engine
            ↓
    Dashboard API
            ↓
    P6 Dashboard

This live API orchestration requires coordination with the P4 backend implementation.

## 15. Conclusion

The P5 Risk & Recommendation Engine successfully converts P3 production prediction outputs into operationally meaningful shortfall information, risk classifications, triggered conditions, and severity-based recommendations.

The engine uses deterministic rule-based logic, making the generated risk levels and recommendations explainable and reproducible.

Recommendation values such as predicted output, planned target, shortfall percentage, downtime, rainfall, blast delay, and configured thresholds are derived from the prediction data rather than manually entered for individual records.

The recommendation action also changes according to the calculated severity of the shortfall and operational conditions.

The P5 core implementation is ready for dashboard consumption.

The current implementation consumes the generated P3 prediction output file. Final live P4-to-P5 prediction orchestration can be added through coordination with the P4 backend implementation.
